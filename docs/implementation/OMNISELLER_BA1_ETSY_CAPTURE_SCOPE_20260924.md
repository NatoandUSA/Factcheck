# BA1-ETSY-CAPTURE — Official Etsy Server-Provider Capture

**Status:** SCOPE LOCKED
**Baseline:** `9517c7c96ec6672e681bebc49f8c9e67866b0939`
**Business blocker:** Current Global Candidate Etsy file intake cannot satisfy the evaluator's trusted exact-query binding requirement.

## Provider decision

Use Etsy Open API v3 `findAllListingsActive` as the preferred trusted provider path:
- server sends the exact `keywords` query directly to Etsy;
- Etsy response is received server-side;
- raw response bytes are hashed;
- capture time is assigned by the server;
- exact query + provider response hash + capture time are bound in a capture receipt;
- result is projected as `ETSY_PUBLIC_SEARCH / OBSERVED_PUBLIC / E1_OBSERVED_PUBLIC`.

YTrends remains `RESEARCH_ONLY` and is not eligible for this capture authority.

## Required credentials

Runtime configuration:
- `ETSY_OPEN_API_KEYSTRING`
- `ETSY_OPEN_API_SHARED_SECRET`

No credential may be committed to the repository or returned to clients.
If credentials are missing or Etsy rejects the key/access level, the provider route fails closed.

## Trust contract

A qualifying official provider capture must include:
- `integrityOutcome=VALID`;
- `rawEvidence.supportScope=QUERY_RESULT_SET`;
- exact query binding state `OBSERVED`;
- query binding authority `SERVER_PROVIDER`;
- non-null deterministic capture ID;
- server-originated capture timestamp;
- raw Etsy response SHA-256;
- active listing count > 0 to satisfy the competition-context portion of Research Readiness.

Official search results do not become Commercial Proof. No sales/revenue field is invented.

## Evaluator change allowed

Do not weaken existing gates.

Add one trusted freshness path for a genuine server-provider capture:
- authority: `SERVER_PROVIDER`;
- basis: `SERVER_RESPONSE_CAPTURE`;
- timestamp/date generated by OmniSeller when the Etsy response is received;
- exact provider query binding + capture ID must also be present.

Existing staff-file freshness semantics remain unchanged.

## Explicit exclusions

- no YTrends authority upgrade;
- no Commercial Proof upgrade;
- no Product Truth changes;
- no scoring/threshold changes;
- no schema migration unless proven necessary;
- no auto-publish;
- no P2 cleanup;
- no client-uploaded query hint may become `SERVER_PROVIDER` or `SERVER_CAPTURE_RECEIPT`.

## Acceptance criteria

1. Missing Etsy API credentials fail closed before any provider claim.
2. Server sends exact normalized query to Etsy official API only.
3. Provider 4xx/5xx/timeouts fail closed and create no candidate evidence.
4. Raw provider response hash is retained.
5. Exact query binding is `SERVER_PROVIDER` and has a capture ID.
6. Server capture timestamp is trusted by freshness logic without impersonating staff attestation.
7. Existing uploaded CSV/HTML query hints remain `authority=NONE`.
8. A mocked valid official Etsy response produces `ResearchReadiness=READY` when fresh and listing count > 0.
9. Same capture does not establish Commercial Proof by itself.
10. YTrends tests and authority semantics remain unchanged.
11. Canonical Node22 suite passes before merge/release.
12. Production remains unchanged until normal review/release governance.
